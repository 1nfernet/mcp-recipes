## 댓글 2 (3/4) 알고 사례
```
제 카드뉴스 자동화 '알고'에는 Threads 게시 코드가 이미 있었습니다.

그런데 확인해 보니, 이 코드는 시도 기록과 승인이 있는 안전한 발행 경로에 연결돼 있지 않았고 --threads 옵션이 승인 없이 게시 코드까지 이어지는 우회 경로였어요.

'게시 코드가 있다'와 '안전하게 자동 발행된다'는 다른 얘기였습니다.
이 옵션은 모든 모드에서 차단했습니다.
```

## 댓글 3 (4/4) 원칙과 마무리
```
알고에서 배운 자동 게시 원칙 3가지

1. 기본은 차단. 드라이런이 기본값이고, 명시적으로 켜야 게시
2. 호출 '전'에 상태를 기록. 끊겨도 올라갔는지 추적 가능
3. 불확실하면 자동 재시도 금지. 사람이 확인해야 중복 게시를 막음

아직 못 해본 것: Threads 실계정 발행 테스트, 구글 캘린더 일정 등록.
레시피 전체와 시작 프롬프트가 필요하시면 댓글 남겨주세요.
```

> 주의: 마지막 댓글의 "구글 캘린더 일정 등록은 못 해봄"은 **지금은 사실과 다릅니다.** 2026-10-09에 3개 등록을 검증했습니다.
> 올리기 전에 "Threads 실계정 발행 테스트, 구글 캘린더 8개 전체 등록"처럼 현재 상태에 맞게 고치세요.
> 알고 사례는 GitHub main 기준 코드를 읽고 확인한 내용입니다. 실제로 게시된 적이 있는지는 확인하지 않았으므로 "게시됐다"고 쓰지 마세요.
